## 2. Forensic Findings & Root Cause Analysis

### 2.1 The Issue Encountered
During API authentication tests, the application failed with:
```
psycopg2.errors.UndefinedColumn: column users.is_email_verified does not exist
```
Inspection revealed that the live database was stuck at revision `04834912199b`, and running `alembic upgrade head` crashed due to an unconditional `op.add_column('tenants', 'deleted_at')` in `e7f8a9b0c1d2` when `deleted_at` was already present in the database.

### 2.2 Dual-Mode Idempotency Remediation
To guarantee migrations never fail regardless of whether they run online against live PostgreSQL or offline during `--sql` dry runs, both pending migrations were upgraded with defensive guards:
```python
def upgrade() -> None:
    bind = op.get_bind()
    is_pg = bind.dialect.name == "postgresql"
    existing_tables = set()
    user_cols = []
    try:
        insp = sa.inspect(bind)
        if insp:
            existing_tables = set(insp.get_table_names())
            if 'users' in existing_tables:
                user_cols = [c['name'] for c in insp.get_columns('users')]
    except Exception:
        # Offline SQL dry-run mode uses MockConnection where inspection is unavailable
        pass

    with op.batch_alter_table('users') as batch_op:
        if 'is_email_verified' not in user_cols:
            batch_op.add_column(sa.Column('is_email_verified', sa.Boolean(), nullable=False, server_default=sa.text('false')))
        if 'mfa_enabled' not in user_cols:
            batch_op.add_column(sa.Column('mfa_enabled', sa.Boolean(), nullable=False, server_default=sa.text('false')))
        if 'mfa_totp_secret' not in user_cols:
            batch_op.add_column(sa.Column('mfa_totp_secret', sa.String(length=255), nullable=True))
        if 'mfa_recovery_codes' not in user_cols:
            batch_op.add_column(sa.Column('mfa_recovery_codes', postgresql.JSONB(astext_type=sa.Text()) if is_pg else sa.JSON(), nullable=True))
```

## 4. Production Migration Deployment Instructions

When deploying to a new environment or applying updates to staging/production:

1. **Verify Database Connectivity:**
   Ensure `DATABASE_URL` is configured in `backend/.env`.
2. **Apply Migrations to Head:**
   ```bash
   cd backend && alembic upgrade head
   ```
3. **Validate No Pending Drift:**
   ```bash
   python scripts/schema_drift.py
   ```
4. **Rollback Command (If required):**
   ```bash
   cd backend && alembic downgrade -1
   ```
