## 1. System Architecture Summary

EducationOS is a multi-tenant institutional SaaS platform engineered for schools, colleges, and coaching academies in Bangladesh:
- **Backend Architecture:** FastAPI (Python 3.12), SQLAlchemy 2.0 ORM, Alembic migrations, PostgreSQL with native Row Level Security (RLS) enforcement per transaction.
- **Frontend Architecture:** Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS, Lucide Icons, bilingual English/Bengali i18n dictionary, IndexedDB offline sync.
- **Background Workers:** Dedicated decoupled daemons for RAG indexing (`rag_worker.py`), transactional communication dispatch (`outbox_worker.py`), and billing lifecycle transitions (`billing_lifecycle_worker.py`).
- **Object Storage:** Unified `StorageService` supporting Cloudflare R2 / AWS S3 with cryptographic SHA-256 fingerprinting and local filesystem fallback.

- **Status:** GREEN / READY

### 2.3 Cloud Object Storage
- **Status:** GREEN / READY
- **Supported Capabilities:**
  - Strict key hierarchy: `tenant/{tenant_id}/{category}/{asset_id}/{safe_filename}`.
  - Magic-byte MIME validation preventing file extension spoofing (PDF, PNG, JPG, DOCX).
  - SHA-256 cryptographic checksum deduplication and tamper detection.
  - Pre-signed expiring download URLs.

### 2.4 Communication & Outbox Subsystem
- **Status:** READY FOR STAGING / LIVE CREDENTIALS PENDING
- **Architecture:** Transactional outbox pattern (`notification_outbox` table) decoupled from API request-response cycle.
- **Providers:** Multi-adapter abstraction supporting Resend, Brevo, SMTP, GreenWeb, Osel, and SSL Wireless.
- **Backoff & Retries:** Automatic retries at 60s, 300s, 900s delays before marking `DEAD_LETTER`.
- **Note:** Real SMS delivery in production requires populating `GREENWEB_API_KEY` or `OSEL_API_KEY` in `.env`.

### 2.5 SaaS Commercial Billing & Entitlements
- **Status:** GREEN / READY
- **Enforcement:** Single-source-of-truth pricing engine (`PricingEngine`) and route dependency guards (`require_entitlement`, `require_active_subscription`).
- **Quotas:** Atomic student capacity checks and monthly AI question quota deduction with PostgreSQL row locks (`with_for_update`).
- **Dunning:** Non-destructive suspension preserves read-only student directories and report cards while preventing write operations during payment lapse.

### 2.6 Offline-First PWA Synchronization
- **Status:** GREEN / READY
- **Capabilities:** Service Worker (`sw.js`) caches static assets; client-side IndexedDB queue (`offlineQueue.ts`) stores attendance roll-calls and teacher diary entries offline, flushing idempotently upon network reconnection.

## 3. Deployment Readiness & Container Infrastructure

- **Container Definitions:** `docker-compose.prod.yml` defines four production services:
  - `educationos_backend`: API web server on port 8000.
  - `educationos_frontend`: Next.js production SSR server on port 3000.
  - `educationos_rag_worker`: Independent RAG parsing and embedding daemon.
  - `educationos_outbox_worker`: Independent email/SMS outbox dispatcher.
  - `educationos_nginx`: Reverse proxy with Let's Encrypt TLS termination.

## 4. Remaining Operational Blockers

1. **Third-Party SMS Gateway Credentials:** Real SMS broadcast to Bangladeshi mobile numbers (+880) requires configuring live credentials for GreenWeb or Osel.
2. **Payment Gateway Merchant Credentials:** Live bKash/Nagad automated checkout requires activating merchant API credentials; manual bank/counter receipts are fully functional.
3. **Domain DNS Mapping:** `schoolos.app` / `educationos.app` DNS records must point to the production server IP address.
