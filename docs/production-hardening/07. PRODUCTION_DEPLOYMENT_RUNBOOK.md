## 1. Required Production Environment Variables (Names Only)

The production environment file (`backend/.env`) must define the following keys. **Never commit actual secret values to source control.**

### 1.1 Database & Pooling
- `DATABASE_URL`: PostgreSQL connection string (with `sslmode=require`).
- `DB_POOL_SIZE`: Database connection pool size (recommended: `10`).
- `DB_MAX_OVERFLOW`: Connection overflow limit (recommended: `5`).
- `DB_POOL_TIMEOUT`: Connection acquisition timeout in seconds (recommended: `10`).
- `DB_POOL_RECYCLE`: Connection recycle interval in seconds (recommended: `1800`).

### 1.2 Authentication & Cryptography
- `SECRET_KEY`: Cryptographically random 64-character hexadecimal string.
- `JWT_ALGORITHM`: `HS256`.
- `ACCESS_TOKEN_EXPIRE_MINUTES`: Access token validity (recommended: `60`).
- `REFRESH_TOKEN_EXPIRE_DAYS`: Refresh token validity (recommended: `7`).

### 1.3 Object Storage (Cloudflare R2 / AWS S3)
- `STORAGE_BACKEND`: `r2`, `s3`, or `local`.
- `STORAGE_BUCKET_NAME`: Target bucket identifier.
- `STORAGE_ENDPOINT_URL`: S3-compatible API endpoint URL.
- `STORAGE_ACCESS_KEY_ID`: Cloud storage access key.
- `STORAGE_SECRET_ACCESS_KEY`: Cloud storage secret key.
- `STORAGE_REGION`: Storage region (e.g., `auto` or `ap-south-1`).

### 1.4 AI Services
- `GEMINI_API_KEY`: Google Gemini API key.
- `GEMINI_RPM_LIMIT`: Requests per minute limiter (recommended: `60`).
- `GEMINI_TPM_LIMIT`: Tokens per minute limiter (recommended: `60000`).

### 1.5 Communication Services
- `EMAIL_PROVIDER`: `resend`, `brevo`, `smtp`, or `mock`.
- `RESEND_API_KEY`: Resend API key (if using Resend).
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`: SMTP credentials (if using SMTP).
- `SMS_GATEWAY_PROVIDER`: `greenweb`, `osel`, `sslwireless`, or `mock`.
- `GREENWEB_API_KEY`: GreenWeb SMS token (if using GreenWeb).
- `OSEL_API_KEY`: Osel SMS API key (if using Osel).

## 2. Step-by-Step Deployment Sequence

### Step 1: Pre-flight Verification
1. Verify working directory is clean and checkout the target release commit:
   ```bash
   git status
   ```
2. Validate environment configuration file exists:
   ```bash
   test -f backend/.env && echo "Environment file present."
   ```

### Step 2: Database Migration
Execute Alembic migrations to bring database schema to head:
```bash
cd backend && alembic upgrade head
```
Verify zero schema drift:
```bash
python scripts/schema_drift.py
```

### Step 3: Container Build & Service Startup
Build and launch all services in detached mode:
```bash
docker compose -f docker-compose.prod.yml build --no-cache
docker compose -f docker-compose.prod.yml up -d
```

### Step 4: Healthcheck Validation
Verify container status and health endpoints:
```bash
docker compose -f docker-compose.prod.yml ps
curl -f http://127.0.0.1:8000/api/v1/health
curl -f http://127.0.0.1:8000/api/v1/ready
```

## 3. Worker Daemon Management

EducationOS runs two background daemons alongside the main web API:
1. **RAG Ingestion Daemon (`rag_worker`):**
   - Sweeps for documents in `QUEUED` state.
   - Run command: `python -m app.workers.rag_worker`.
2. **Outbox Notification Dispatcher (`outbox_worker`):**
   - Sweeps for outbox items in `PENDING` state and dispatches email/SMS.
   - Run command: `python -m app.workers.outbox_worker`.

Both workers respond to `SIGTERM` and `SIGINT` with graceful shutdown, ensuring in-flight database transactions are committed or rolled back safely before exit.

## 4. Rollback Strategy

In the event of an unexpected critical incident post-deployment:

1. **Revert Application Containers:**
   ```bash
   docker compose -f docker-compose.prod.yml down
   git checkout <PREVIOUS_STABLE_COMMIT>
   docker compose -f docker-compose.prod.yml up -d --build
   ```
2. **Revert Database Migrations (If non-destructive):**
   ```bash
   cd backend && alembic downgrade -1
   ```
3. **Verify Service Health:**
   ```bash
   curl -f http://127.0.0.1:8000/api/v1/health
   ```
