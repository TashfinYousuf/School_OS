# RC3 Risk Register

| Risk ID | Risk Event | Likelihood | Impact | Mitigation Strategy | Owner Decision Needed? |
|---|---|---|---|---|---|
| RSK-01 | Applying `SET LOCAL ROLE authenticated` on Supabase pooler fails permissions on sequences/tables or breaks existing background queries lacking `tenant_id` | Medium | High | Grant explicit table/sequence privileges to `authenticated` AND create `AS PERMISSIVE` policies for all 35 uncovered tables in the same additive Alembic migration; test both positive & cross-tenant negative queries directly against Postgres in rolled-back transactions before rollout. | No (verified via rollback SQL + migration test) |
| RSK-02 | Mutating existing `role='admin'` student/guardian accounts or deleting orphan `'Reconstruction Test Academy'` tenants directly on remote Supabase causes unintended pilot disruption | Low | Critical | Do **NOT** destructively delete tenants or silently rewrite existing live `users` rows without explicit owner approval; generate idempotent SQL/Python remediation script and flag to owner in final report unless pre-authorized. Keep automated test suites strictly rollback-isolated or UUID-cleaned. | **YES** (for live Supabase row cleanup) |
| RSK-03 | Tightening webhook secret defaults (`payment_providers.py`, `finance.py`) breaks existing `test_stage06_finance.py` or `test_stage12_subscription_billing.py` webhook tests | High | Medium | Fail closed (HTTP 503) in production/default code when webhook secret env var is empty, and explicitly configure test env secrets via `monkeypatch.setenv` inside test suites (`test_stage06_finance.py`, etc.). | No |
| RSK-04 | Tightening `GuardianStudentLink.verification_status == 'VERIFIED'` breaks pre-existing linked children whose link rows were inserted via legacy flows with `NULL` | Medium | High | Backfill any legitimate legacy `guardian_students` link (`Taki Hussain -> Talha Hussain`) and explicitly set `verification_status='VERIFIED'` on all admin admission/CSV import creation paths (`students.py`, `institution.py`) before removing `IS NULL` tolerance in queries. | No (non-destructive additive backfill) |
| RSK-05 | Owner has not ratified dynamic per-student pricing tiers (`12 / 10 / 8 BDT` progressive vs flat tier, `IS_OWNER_APPROVED=False`) or provided bKash/Nagad/SSLCommerz/SMS credentials | High | High | Standardize calculation engine on `Decimal` SSOT in backend + preserve `IS_OWNER_APPROVED` explicit commercial gate; classify `Commercially Ready` honestly (`BLOCKED` / `CONDITIONAL`) until owner sign-off and credentials are provided. | **YES** (commercial sign-off + credentials) |
| RSK-06 | Remote-only Supabase Postgres testing during test runs creates residual rows on crash | Medium | Medium | Wrap tests cleanly, generate unique `uuid4` identifiers per test, and clean up created test artifacts in `finally` / pytest fixtures. Avoid touching existing pilot tenants (`Kids Shine` / `CRSC`). | No |
